# 论文知识库工作规则（日常协作协议）

本文件是 thesis-kb 的长期工作规则，规定贯穿全程的资料加工与质检纪律；各阶段的操作程序见 playbook.md。知识库搭好之后，每次协助用户处理资料、推进写作时遵守。

## 总纲：输入 → 加工 → 使用 → 反馈

知识库不是收藏夹，是生产线：每个环节的产出是下一个环节的输入。

## 一、输入：带任务输入

- 收什么资料，由"下一个产出物需要什么"倒推；与当前阶段无关的资料进收件箱后排期，不优先处理。
- 来源分级：一手（官方披露原文）、二手（研报、报道、分析）、转述（聊天记录、口头信息）分开置信，转述类永远标"待核"。
- 收件箱是临时入口：分拣完毕后从收件箱清走，收件箱不留存货。

## 二、加工：入库前的质检闸口

资料进入主库（01—04 子目录）之前，必须完成三个动作：

1. **复述**：用自己的话概括要点（摘录卡片不超过三行原文要点）。
2. **标证据等级**：A＝已核到原始出处并记录页码、段落或记录位置；B＝发行人/中介/权威媒体发布；C＝已定位未核验；缺口＝未取得（不能推定不存在）。
3. **事实核查**：AI 生成或转述的内容，事实、文献、数据逐条核对原文后才准入库；核查记录随文件保存。常见 AI 错误：编造文献条目、把行业常识包装成个人发现、时间表述含糊、公司状态过时（未上市/已上市）。

## 三、使用：输出倒逼输入

- 目录按产出链条组织：01 要求 → 02 选题 → 03 素材 → 04 提纲 → 05 正文。推进时永远先问"当前卡在链条哪一环"。
- 结构覆盖指标：**提纲里已有素材的小节占比**，不是字数。
- 素材挂载：每张摘录卡片注明"挂载的提纲小节"；小节挂满一半再开始写正文。
- 引用纪律：同一份材料全库只出现一次，其他位置用链接引用。

## 四、反馈：版本即思考

- 文件改版升版本号，并记录**为什么改**（挪动日志/修订记录），不只记改了什么。
- 导师反馈当天转写成文字，"原话"与"我的理解"分开写；导师意见导致的修改在相关文件里注明来源。
- 每周回顾一次进度表，更新"有素材的小节数"和卡点。

## 五、AI 协作边界

- AI 的输出只是**候选**：经用户验证、并在真实写作中使用过的内容，才算入库的知识。
- 判断、定调、专业口吻由用户负责；AI 起草的立论、个人观点类表述，用户必须亲自过一遍。
- 涉及用户个人信息（单位、职务、时间线）时，默认模糊化处理，由用户决定披露精度。

挂载使用可定位的 Markdown 链接或双链。分别记录来源核验等级与该来源能支持的具体判断。未明确评级的卡片保持「未评级」。
